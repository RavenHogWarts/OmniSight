# 隐私白皮书

本文是 OmniSight 对用户的隐私承诺与边界说明：**记录什么、能推出什么、怎么关掉、怎么删掉**。
对应的内部设计文档是 [dev/08-privacy-and-security.md](../dev/08-privacy-and-security.md)；
两者冲突时以本文对你承诺的为准。

**一句话立场：数据只留在你的电脑上。无账号、不联网、无遥测、无崩溃上报、无版本检查回连。**
程序里不存在任何出站网络代码——这一点在持续集成里被静态检查强制，不是"我们承诺不连"，
而是"想连也连不了"。

---

## 1. 记录什么

所有采集项按敏感度分为四级。**每一级都能在首启说明与设置页里看到自己此刻的状态**——
那两处的内容是程序按你的实际配置算出来的，不是固定文案。

| 级别 | 数据项 | 能推出什么 | 当前默认 |
| --- | --- | --- | --- |
| **L1 聚合** | 按天/月/年的应用时长、按键计数、应用×键计数 | 使用习惯、偏好、输入强度 | 开（关了就没有产品） |
| **L2 会话** | 应用 + 起止时间（应用用时长的来源） | 作息、专注时段 | 开 |
| **L3 窗口标题** | 会话伴随的窗口标题 | **浏览过的网页标题、编辑的文件名**——等价于一份浏览历史 | **关** |
| **L4 原始按键** | 每次按键的键位、纳秒级时间戳、按压时长、**所属应用** | **击键序列，可还原输入过的文本；击键动力学特征** | **开**（保留期 90 天，见下） |

### 1.1 两项需要特别说明的默认值

**L3 窗口标题默认关闭。** 窗口标题是被低估的泄露面：浏览器窗口标题就是网页标题。
它的统计价值低而隐私敏感度高，因此默认不记。需要"按文件/项目维度的时长"时可以在
设置页开启，开启后首启说明会如实把它挪进"会记录"一栏。

**L4 原始按键默认开启，保留期 90 天。** 这是经过权衡的决策，理由必须向你交代完整：

- 关闭 L4 只损失两项功能——组合键识别与毫秒级节奏分析；热力图、应用×键、人体工学、
  KPM 全部照常工作（聚合表始终完整维护，与原始事件无关）。
- 但原始事件是本项目**唯一能还原输入内容**的数据（见 §2），"默认关"会让多数用户
  永远发现不了这个风险开关的存在，"默认开 + 明确告知 + 保留期"让这件事暴露在
  你第一次打开仪表盘的那一屏上。
- **诚实的限制：当前版本（0.1.0-alpha）记录保留期的值，但还没有执行按期清理**——
  清理任务排在后续版本。也就是说，设置为 90 天的当下效果是"不删"。如果你需要
  确定性删除，请关闭 L4，或手动删除数据目录里的数据库文件（见 §4）。
  我们宁可把这条限制写在最显眼的位置，也不写一个"保留 90 天"而实际永不删除的空话。

### 1.2 永远不记录的东西

无论各开关如何组合，以下内容**从不落库**：

- **按键对应的字符内容与输入顺序的"文本"**——数据库里存的是键位编号，不是字符串
  （但见 §2：原始事件在技术上可被还原，这是它与生俱来的性质，不是承诺能撤销的）
- 剪贴板、屏幕内容、麦克风、摄像头、文件内容
- 任何形式的网络上传（无遥测、无 analytics、无崩溃上报）
- 提权窗口（UAC 确认框）里的按键——它跑在系统的安全桌面上，普通桌面上的程序一律
  收不到那几次输入，**管理员模式也不例外**（见 §8）

## 2. 能推出什么（诚实告知）

这一节是全文最重要的一节。**我们不说"数据是匿名的、安全的"这类空话**，而是把
L4 原始事件在技术上意味着什么写清楚：

1. **按键顺序可还原。** 原始事件带纳秒时间戳，按时间排序就是完整的击键序列。
2. **输入内容可还原。** 结合键盘布局映射，字母键序列可以直接读出你输入过的英文、
   密码、URL、命令行——不含大小写与输入法转换，但对这几类文本几乎是明文。
3. **击键动力学特征。** 纳秒时间戳 + 按压时长构成学术界公认可用于**身份识别**的
   生物特征。
4. **应用归属放大了以上全部。** 事件带有"按在哪个应用里"，使风险从"某时刻打了
   什么"升级为"在哪个应用里打了什么"——例如可以定位"密码管理器窗口里的那段击键"。

能读到这个文件的任何人（包括你自己、包括拿到你电脑的任何人）都能做上述还原。
这不是缺陷，而是"带应用归属的原始击键数据"的定义。**我们的责任是不隐瞒这一点，
并把是否接受它的选择权交给你**（关闭方式见 §3）。

## 3. 怎么关掉、怎么缩减

隐私控制若藏在设置深处就等于不存在。三个层次，随手可用：

**暂停（最粗粒度，最快）**

- 托盘菜单 →「暂停记录」：立即停止一切写入，托盘图标变灰。
- **暂停期间已缓冲的事件被丢弃，而不是延后落盘**——你点暂停是希望这段不被记录，
  不是希望晚点记。
- 恢复输入后从新会话开始，暂停的那段时间不产生任何数据。

**排除（按应用）**

- 应用视图 → 展开某个应用 → 排除开关；或配置文件 `privacy.excluded_processes`
  直接写进程名列表。
- 排除发生在**采集层**：被排除的应用不产生会话、不产生按键记录，而不是仅在
  界面上隐藏。历史数据保留，可随时取消排除。

**缩减（按级别）**

- 设置页 → 隐私：关闭「窗口标题」（L3）、关闭「原始按键事件」（L4）。
- 关闭 L4 后热力图等功能**完全正常**（见 §1.1），只是不再留下可还原的序列。
- 配置写在 `config.json` 里，你可以直接手改并重启；改错了程序会报错并指出
  具体字段，不会静默重置。

## 4. 怎么删掉

| 你想删的 | 当前版本的做法 |
| --- | --- |
| 全部数据 | 退出程序后删除数据目录（默认就是程序同级目录，因为发布包带着 `portable.marker`；删掉该标记后是 `%LOCALAPPDATA%\OmniSight\`）。删掉即彻底，无残留。 |
| 仅原始按键事件 | 关闭 L4 后删除 `data/omnisight.db` 里的原始事件表，或直接删库重来（聚合统计会一并失去）；**按应用/按时间段的细粒度删除接口排在后续版本**。 |
| 导出一份带走 | 设置页 → 导出 CSV / JSON。导出直接写你指定的路径，不落临时目录。 |

两点如实说明：

- 删除是**真删除**：数据库建库时即开启 `PRAGMA secure_delete=ON`，删除会覆写页内容。
- "仅删原始事件、保留统计"的界面入口（一键清空敏感数据）尚未提供，这是后续版本的
  已知待办，不是被刻意省略。

## 5. 本机防护：不能假设"本地就是安全的"

数据敏感，因此要防的不只是"上传"——还有你电脑上的**其他程序与网页**。

| 措施 | 防什么 |
| --- | --- |
| 服务只监听 `127.0.0.1`（回环地址），配置里写非回环地址会**拒绝启动** | 局域网访问 |
| 打开仪表盘需要一次性令牌（托盘自动带上，页面加载后立即从地址栏抹掉） | 任意网页通过 JS 读取你的数据 |
| 校验 HTTP `Host` 头，非本机主机的请求返回 421 | DNS rebinding 攻击 |
| 严格 CSP（禁止内联脚本）+ 不设任何跨源许可 | 恶意页面注入 |
| 写操作（改设置、导出、确认说明）额外校验同站 | 伪造的跨站写请求 |
| 数据目录权限收紧为仅当前用户 | 同机其他账户 |
| 运行期 `runtime.json`（令牌 + 端口 + pid）仅当前用户可读 | 同上；它防的是网页而非本机程序，见下 |

**关于 `runtime.json`**：程序运行时会在数据目录写一个含访问令牌的小文件（停机即删）。
这不会削弱防护：令牌防的是**网页**，而网页读不到本地文件；能读到这个文件的程序
本来就能直接读数据库文件。它的作用是让程序自身与本机工具能访问自己的接口，
不必另开后门。

**数据库不加密，理由如下**：加密只能防"文件被拷走后离线读取"，但密钥必须存在本机
且程序要自动解密（后台服务不能每次开机要密码）——钥匙与锁同放，对本机恶意程序
毫无阻挡，只增加复杂度。如果你担心**电脑丢失**场景，正确的解法是操作系统层的
BitLocker 全盘加密，而不是应用层加密。

## 6. 日志与崩溃报告

容易被忽略的泄露渠道，逐条交代：

- **运行日志**（`logs/omnisight.log`，滚动保留）：**永不包含窗口标题与键位序列**；
  应用只以数字 id 出现。所有日志在写出前经过一道内容过滤，命中敏感字段名一律替换
  为 `<redacted>`——人写代码会忘，过滤器不会。
- **崩溃报告**（`logs/crash-<时间戳>.txt`，最多保留 10 份）：只含异常类型、位置与
  源码行，**不含局部变量**（局部变量里可能有窗口标题或键位）。可以直接附在
  问题报告里。
- **不上传**：崩溃报告只落在本机，程序没有任何自动上报机制。
- **导出文件**：直接写你指定的路径，不经临时目录。

## 7. 供应链

- 依赖全部精确固定版本，发布物**零 CDN / 零外部资源引用**——前端没有任何一行代码
  从网络加载。
- 依赖许可清单随产物分发（`THIRD_PARTY_NOTICES.md` / `THIRD_PARTY_LICENSES.txt`），
  每次发布重新生成；GPL 系依赖会导致构建直接失败而不是"发出去再说"。
- 程序内置一个键盘后端兜底组件（`pynput`，低级键盘钩子）。它在 Windows 的主路径
  （Raw Input）注册失败时才会加载，且一旦启用，界面会**明确告知**"当前后端无法
  区分左右修饰键"——静默降级在这里尤其不可接受。

## 8. Windows 权限模型：为什么必须主动告知

Windows 上读取键盘输入（Raw Input）**不需要管理员权限、不弹任何系统授权框**。
这是方便，也是问题：**你无从从系统层面感知一个程序在监听键盘**——包括 OmniSight，
也包括任何其他程序。

正因如此，主动、显式地告知才成了本项目的义务而不是礼貌：首启那一屏说明、
这一份白皮书、设置页里每个开关旁的后果描述，都是同一个立场的结果——
**工具的价值和风险都真实存在，选择权在你**。

### 8.1 管理员模式：一个你必须自己按下的按钮

那条"不需要管理员权限"有一个例外，我们把它讲全，而不是留给用户自己撞上去：**以管理员
身份运行的程序里敲的键，普通权限的 OmniSight 收不到**（系统不允许低完整性级别的进程
收到发往高完整性级别进程的输入）。托盘的「以管理员身份重启」是补这个缺口的唯一办法。

关于它的四条承诺：

- **永远是你点的。** 程序不会自己提权、不会因为"能力受限"弹窗催你提权，也不会把"没提权"
  标成一条降级警告——普通权限是推荐状态，把它显示成缺陷等于在催每一个用户交出更多权限。
- **托盘那一项只对本次运行有效。** 不写进配置、不改自启项。"每次开机都以管理员身份运行"
  是另一个决定，它有自己的开关（设置页 →「登录时以管理员身份启动」），并且**只有装在
  普通用户不可写的目录里时才可开**：否则那条无提示提权的启动项等于给任何能改那个目录的
  程序一条管理员通道。开关是灰的时候界面会写出当时的原因。
- **提权不改变记录什么。** 采集的边界与开关完全一样：管理员模式只是让原本收不到的那部分
  按键能被收到，不会新增任何一类数据，也不会突然开始记录窗口标题或原始事件。
- **提权状态一直可见，而且由程序打开的东西都降回普通权限。** 托盘悬浮提示在管理员模式下
  显示「管理员模式」，菜单里那一项也会改成"本次已在管理员模式运行"。数据目录与日志目录
  交给普通权限的资源管理器打开；仪表盘地址交给桌面上那个普通权限的 shell 去打开，因此
  浏览器**不会**跟着提权（自 M7；在这之前它会）。只有拿不到这条通道的机器上（资源管理器
  没在运行、组策略禁了脚本宿主）才退回直接打开，那时浏览器若没在运行会跟着提权——
  "打不开"比这更糟，所以宁可退回。想完全避开就先打开浏览器，或退出管理员模式再看仪表盘。

（macOS 与 Linux 的权限模型不同：macOS 有系统级"输入监控"授权，Linux/Wayland
需要设备访问权限。它们在后续版本支持时会有各自的说明。）

## 9. 与两个旧项目的承诺对照

OmniSight 由 TimeLens（应用时长）与 KeyTrace（键盘统计）合并而来。合并改变了
隐私边界，必须把变化说清楚而不是悄悄继承：

| 旧承诺 | 现状 |
| --- | --- |
| TimeLens：只在本机记录 | **仍然成立**（本文件 §1 的一句话立场） |
| TimeLens：记录窗口标题 | **变更**：默认不再记录，改为显式开关 |
| KeyTrace：原始按键事件永久保存 | **变更**：保留期可配（默认 90 天，清理任务见 §1.1 的诚实限制） |
| KeyTrace：「不保存应用名称、窗口标题或输入文本内容」 | **不再成立，主动收回**：按键事件现在带有应用归属。这一条是合并中唯一需要收回的承诺，因此放在最显眼的位置——老用户不应以为行为未变 |
