# 常见问题

安装、杀软、权限、数据位置相关的常见问题。隐私边界的完整说明见
[privacy.md](privacy.md)。

---

## 安装与启动

### 怎么安装

不用安装。发布只提供一件产物 `OmniSight-portable.zip`：解压到任意**可写**目录
（桌面、文档、U 盘都行），双击 `OmniSight.exe` 就能用。

别解压到 `Program Files` 这类需要管理员权限的位置——压缩包里有 `portable.marker`，
程序会把数据写在自己同级目录，而那些位置普通用户写不进去，启动会失败。

裸 `OmniSight.exe` 不单独发布：它带不走 `LICENSE`、第三方许可清单与 `README.txt`，
而那几份是分发义务，不是可选附件。

### 双击 EXE 后什么都没发生

程序是**无控制台**的（弹一个黑色命令行窗口更糟），出错时它把原因写在数据目录的
`STARTUP_ERROR.txt` 里——这是"双击了没反应"时你唯一能自己发现的线索。

1. 打开数据目录（默认就是程序同级目录；删掉 `portable.marker` 后是
   `%LOCALAPPDATA%\OmniSight\`）
2. 看有没有 `STARTUP_ERROR.txt`，按里面的提示处理
3. `logs\` 目录里还有运行日志与崩溃报告（`crash-<时间戳>.txt`）

常见原因：解压位置不可写（见上）、端口被占用（见下）、`config.json` 写错（程序会
指出具体字段）、上一个实例还没退干净。

### 浏览器打开是 401

正常且有意。仪表盘访问需要一次性令牌，**从托盘 →「打开 OmniSight」进入会自动
带上**；手输地址看到 401，说明这道防线在正常工作——它挡住的是任意网页对本机
接口的读取（详见 [privacy.md §5](privacy.md)）。

### 端口被占用（默认 6100）

程序**不会静默换端口**——静默换会让你找不到仪表盘，还可能与别的程序互相干扰。
占用时它会报错退出并说明原因。处理：

1. 常见情况是上一个 OmniSight 还在运行（托盘里找找），退出它即可
2. 确实被别的程序占用：编辑数据目录的 `config.json`，把 `server.port` 改成
   其他端口（参照 `config.example.json` 的格式），重启程序

### SmartScreen 警告（"Windows 已保护你的电脑"）

本程序未购买代码签名证书。对未签名程序，Windows 会显示蓝色警告框：

1. 点「更多信息」
2. 点「仍要运行」

**先核对校验值再这么做**：在 PowerShell 里运行
`Get-FileHash .\OmniSight-portable.zip -Algorithm SHA256`，与发布页的
`OmniSight-portable.zip.sha256` 内容比对（也可与 [scan-record.md](scan-record.md)
里的记录比对）。签名缺失意味着"确认拿到的确实是这份产物"只能靠校验值。

## 杀软与安全软件

### 杀毒软件把 OmniSight 报为键盘记录器

**这个报警从杀软的角度看不是误判**：OmniSight 确实在全局读取键盘输入——这正是
它的功能（键盘使用统计）。它与传统意义上恶意键盘记录器的区别在于：

- 数据**只写在本机数据库**，程序不含任何网络上传代码（这不是承诺，是代码结构
  上就不存在出站网络调用，可在源码里验证）
- 无账号、无遥测、无崩溃上报
- 记录的是**键位编号**而非字符内容，且提供暂停、排除、分级关闭（见
  [privacy.md §3](privacy.md)）

尽管如此，是否信任由你决定。应对方式按你的意愿选：

- **信任它**：把 `OmniSight.exe` 加入杀软白名单/排除项（各软件路径不同，通常在
  设置 → 排除项/信任区 → 添加文件）。Windows Defender 是"病毒和威胁防护 →
  管理设置 → 排除项"。
- **不放心**：不添加白名单，改为从源码运行（见 [README](../README.md)）——
  你可以逐行审计它在读什么、写什么、（不）往哪里发。

每次发布前对产物做的扫描、以及产物的校验值，记录在
[scan-record.md](scan-record.md)。那里也给出按 SHA-256 查询 VirusTotal 的地址——
**查询用的是哈希，不会把你手上的文件上传给任何人**。

### 为什么不买代码签名证书

成本与收益的权衡记录在案：个人开发者的证书年费不低，而校验值 + 源码运行两条路
已覆盖"确认产物真实性"的需求。若未来用户规模变化，签名会重新评估。

### 远程桌面 / 虚拟机里按键数据不完整

Raw Input 在某些环境（远程桌面会话、部分虚拟机、部分带反作弊的系统加固）下可能
收不到事件。这是系统层面的限制，不是故障。程序会如实把键盘采集状态反映在
状态接口与界面降级提示里；远程桌面场景建议在物理机本机会话中使用。

## 权限与采集

### 需要管理员权限吗

**不需要。** 程序以普通用户权限运行：Raw Input 对普通进程开放，托盘、本地
Web 服务、注册表自启（HKCU）都不需要提权。**请勿用管理员身份运行**——
没有任何功能因此受益，只会让"读键盘的程序"拿到不必要的权限。

### UAC 提权窗口（安装确认框等）期间的按键会被记录吗

**不会，也记录不了**：系统不允许普通完整性级别的进程收到更高完整性级别进程的
输入。这是正常行为，不是缺陷。

### 全屏游戏里的按键能被记录吗

能——这正是选用 Raw Input 而不是普通钩子的原因：它不注入目标进程，全屏独占
模式下依然有效。若个别游戏环境下收不到（见上条"远程桌面/虚拟机"），界面会
如实显示采集不可用。

### 密码会被记下来吗

数据库记录的是**键位编号、次数与时长**，不存字符内容。但必须诚实：开启了原始
事件记录（L4）时，键位序列在技术上可以被还原成输入过的文本——包括密码。
完整的说明与关闭方法见 [privacy.md §2](privacy.md)。

密码管理器等敏感应用可以通过「排除」彻底不留任何记录（采集层排除，非界面隐藏）。

## 数据与卸载

### 数据到底存在哪

| 情况 | 位置 |
| --- | --- |
| 默认（解压后同级有 `portable.marker`） | 解压目录：`config.json`、`data\`、`logs\` |
| 删掉 `portable.marker` 后 | `%LOCALAPPDATA%\OmniSight\` |

托盘 →「打开数据目录」直接跳过去。

### 数据能不能放到 Windows 惯例的位置

能。删掉程序同级的 `portable.marker`，重启后数据落在 `%LOCALAPPDATA%\OmniSight\`。
**已有的 `data\` 不会被自动搬走**——把整个 `data\` 文件夹移到新位置即可继续使用
（或留在原地当作备份）。

反过来也一样：在程序同级放一个名为 `portable.marker` 的空文件，数据就回到同级目录。
发布包里默认带着这个文件，因为"解压即用、卸载即删干净"是这类工具最省心的形态。

### 怎么完全卸载

1. 托盘 →「退出」
2. 关掉开机自启：托盘取消勾选「开机自启」，或删除注册表
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `OmniSight` 值
3. 删除数据目录（位置见上表；默认形态下它就在解压目录里）
4. 删除解压出来的整个目录

程序不写系统目录、不装服务、不装驱动，除第 2 步那个自启项外**不留任何注册表项**。
第 3、4 步执行后没有任何残留。

### 从旧版 TimeLens / KeyTrace 迁移数据

OmniSight 带导入向导：启动后在设置 →「从旧版导入数据…」，或首页检测到旧库时
会出现提示横幅。向导会先预览将导入什么、明确标注有损项（旧数据无按键时长、
无应用归因等），确认后才执行；导入前自动备份，完成后可撤销。

旧 KeyTrace 在迁移期也可以直接指向 OmniSight 的兼容接口继续取数据
（把它的 `timelens_port` 配置改为 6100）。

**有两处口径与旧版不同，数字对不上不是导入出错：**

- 键盘面板的"小时分布"是**所选那一天的 0–23 时**，而旧 KeyTrace 是"最近 24 小时"
  的滚动窗口。改成前者是为了与周期选择器一致（选哪天看哪天）。
- 周的起点统一为自然周（默认周一，设置里可改）。旧 TimeLens 的"周"是"选中日
  往前 6 天"的滚动窗口，所以同一个"本周"两边的数字本就不该相等。

### 数据库文件有多大

聚合数据很小（重度使用一年 < 12 MB）。大头是原始按键事件（若开启）：重度使用
（约 4 万次按键/天）一年约 880 MB。关闭原始事件记录后不再增长。定期清理
（按保留期 90 天）排在后续版本，当前需要控制体积请关闭 L4 或手动删库
（见 [privacy.md §4](privacy.md)）。

### 程序崩溃了数据会丢吗

已落盘的数据不会丢（数据库 WAL 模式保证）；崩溃瞬间还在内存里的部分最多丢
约 1–2 秒。崩溃后重启即可，数据库会自动完整性检查，损坏时会改名为
`omnisight.db.corrupt-<时间戳>` 并新建空库（原文件保留，便于抢救）。
`logs\` 下的 `crash-*.txt` 是诊断材料，不含敏感内容，可直接附在问题报告里。

## 其他

### 支持 macOS / Linux 吗

**当前版本只支持 Windows**（10 版本 1809 及以上 / 11）。macOS 与 Linux 在规划中、
尚未实现——程序的架构为它们留好了位置，但那不等于现在能用。分级承诺见
[README](../README.md) 的平台支持表。

### 界面语言能切换吗

当前只有中文。多语言支持排在后续版本。

### 发现了 bug / 隐私文档与实际行为不一致

提 issue。附上 `logs\` 里的崩溃报告（若相关）——它只含异常类型与位置，
不含窗口标题、按键内容或局部变量，可以直接上传。
